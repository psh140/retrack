# 개발 진행 현황

Retrack(연구과제 관리 시스템)의 전체 개발 이력을 시간순으로 정리한 문서다.

- 이 문서는 **프로젝트 전체를 조망하는 타임라인**이다.
- 각 단계에서 어떤 파일을 만들었는지 같은 **파일 단위 상세 체크리스트**는
  [`backend/CLAUDE.md`](../backend/CLAUDE.md)·[`frontend/CLAUDE.md`](../frontend/CLAUDE.md)의
  개발 현황 섹션에 그대로 둔다. 개발 중 "이 API가 구현돼 있나"를 확인하는 용도라 코드 옆에 있는 편이 낫다.
- 배포 절차의 실제 수행 기록은 [`배포-작업기록.md`](배포-작업기록.md)에 별도로 정리했다.

## 4. 보안 조치 (2026-07-27)

저장소가 **공개 상태**임을 확인하고, 커밋된 평문 자격증명을 코드에서 지우는 데 그치지 않고
**값 자체를 폐기·재발급**했다.

- `docker-compose.yml`의 `POSTGRES_PASSWORD`·`DB_PASSWORD`·`JWT_SECRET`을 `.env` 참조로 교체
- `spring-db.xml`의 하드코딩된 DB 접속 정보를 환경변수 참조로 교체
  — compose가 `DB_*` 환경변수를 넘기고 있었지만 백엔드는 이를 **읽지 않고** XML에 적힌 값을 쓰고 있었다.
  compose만 고쳤다면 DB 접속이 옛 비밀번호를 향해 실패했을 것이다.
- git 히스토리는 재작성하지 않기로 결정 — 값을 폐기한 이상 히스토리의 옛 값은 무의미하고,
  GitHub 캐시·기존 클론본은 회수가 불가능하다.

## 6. 남은 과제

배포는 완료했고, 아래는 필수는 아니지만 개선 여지로 남아 있는 항목이다.

- **CI/CD 미적용** — 현재는 수동 배포다. WAR를 로컬에서 빌드해 `scp`로 올리고 컨테이너를 재생성한다.
  GitHub Actions로 자동화할 수 있다.
- ~~백엔드 CORS 설정~~ — **2026-08-03 해결.** `allowed-origins`에 운영 도메인을 추가하고 재배포했다.
  Nginx의 `Origin` 헤더 제거와 함께 이중으로 유지한다(배포-작업기록 8-1 참조).
- **Tomcat RemoteIpValve 미설정** — `X-Forwarded-Proto`를 전달하고 있지만 Tomcat이 이를
  `request.getScheme()`에 반영하지 않는다. 백엔드가 원 프로토콜을 알아야 하는 기능이 생기면 필요하다.
- **모니터링·로그 수집 없음** — 컨테이너 로그를 `docker logs`로 직접 보는 수준이다.
