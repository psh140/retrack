# 개발 환경 세팅 (새 기기에서 시작하기)

Windows / Mac 등 새 환경에서 Retrack을 처음 띄울 때 따라가는 문서다.
작성: 2026-07-27 (Mac 환경 추가 세팅 기준)

관련 문서: [`배포-체크리스트.md`](배포-체크리스트.md) — EC2 배포 절차

---

## 0. 원칙 — `.env`는 옮기지 않는다

`.env`는 `.gitignore`에 걸려 있어 저장소에 올라가지 않는다. **기기 간에 파일을 복사하지 말고,
각 환경에서 새로 생성한다.** 값의 성격이 환경마다 독립적이기 때문이다.

| 키 | 환경 간 공유 | 이유 |
|---|---|---|
| `DB_PASSWORD` | 불필요 | 기기마다 postgres 볼륨이 별개다 |
| `JWT_SECRET` | 불필요 | 해당 환경에서 발급한 토큰만 검증한다 |
| `MAIL_USERNAME` | 동일 값 | 같은 Gmail 계정 |
| `MAIL_PASSWORD` | 기기별 발급 권장 | 앱 비밀번호는 여러 개 발급 가능하며, 기기별 개별 폐기가 가능하다 |

EC2 운영 환경도 마찬가지로 서버에서 새로 생성한다.
로컬 값을 그대로 올리면 로컬이 뚫렸을 때 운영까지 함께 뚫린다.

## 1. 사전 준비 (Mac)

```bash
# Docker Desktop — 설치 후 실행까지 해둘 것
brew install --cask docker

# JDK — Java 11 타겟이지만 21로 빌드된다 (source/target 11 설정)
brew install --cask temurin@21

# Maven, Node
brew install maven node
```

### ⚠️ Homebrew Maven의 JDK 버전 함정

Homebrew로 설치한 Maven은 Homebrew 기본 JDK(현재 25)를 물고 실행된다.
Java 11 프로젝트를 컴파일할 때 내부 컴파일러 API가 맞지 않아 아래 오류가 난다.

```
[ERROR] Fatal error compiling: java.lang.ExceptionInInitializerError:
        com.sun.tools.javac.code.TypeTag :: UNKNOWN
```

**먼저 확인한다.**

```bash
mvn -v   # "Java version:" 줄이 21인지 볼 것
```

25가 나오면 `JAVA_HOME`을 21로 고정한다.

```bash
# 일회성
JAVA_HOME=$(/usr/libexec/java_home -v 21) mvn -f backend/pom.xml clean package

# 영구 적용 (~/.zshrc)
echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 21)' >> ~/.zshrc
source ~/.zshrc
```

> 참고: 2026-07-27 Windows(JDK 21)에서는 이 문제 없이 빌드·테스트 11개가 모두 통과했다.
> 상세 이력은 [`troubleshooting-7단계-파일관리API.md`](troubleshooting-7단계-파일관리API.md) 참고.

### Apple Silicon

`postgres:14`, `tomcat:9-jdk11` 모두 arm64 이미지가 있어 별도 설정 없이 동작한다.

## 3. `.env` 생성

```bash
cp .env.example .env
```

값 생성:

```bash
openssl rand -hex 16   # → DB_PASSWORD
openssl rand -hex 32   # → JWT_SECRET
```

`.env`를 열어 채운다. `JWT_SECRET`은 32자 이상이어야 한다
(미달 시 `JwtUtil` 생성자가 `IllegalStateException`을 던지며 기동 실패한다).

```
MAIL_USERNAME=psh140140@gmail.com
MAIL_PASSWORD=<아래 4번에서 발급>
DB_PASSWORD=<openssl rand -hex 16 결과>
JWT_SECRET=<openssl rand -hex 32 결과>
```

> **Finder에서 `.env`가 안 보일 때**: 점으로 시작하는 파일은 기본 숨김이다.
> Finder에서 `Cmd + Shift + .` 로 토글하거나, 터미널에서 `open -e .env`로 연다.

## 4. Gmail 앱 비밀번호 발급

기존 값을 옮기지 말고 이 기기용으로 새로 발급한다.

1. Google 계정 → 보안 → 2단계 인증 (활성화되어 있어야 앱 비밀번호 메뉴가 나온다)
2. 앱 비밀번호 → 이름을 `retrack-mac` 등으로 지정하고 생성
3. 표시된 16자리를 `.env`의 `MAIL_PASSWORD`에 입력

발급된 값은 **생성 직후 한 번만** 표시된다. 놓치면 새로 발급하면 된다.

## 7. 동작 확인

```bash
# 백엔드 직접 호출
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@test.com","password":"admin1234"}'
```

`{"success":true,...,"token":"eyJ..."}` 가 나오면 DB 커넥션과 JWT 발급이 모두 정상이다.

```bash
# Nginx 프록시 경유까지 확인
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@test.com","password":"admin1234"}' \
  | sed -E 's/.*"token":"([^"]+)".*/\1/')

curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/api/dashboard \
  -H "Authorization: Bearer $TOKEN"    # 200 이어야 한다
```

브라우저: http://localhost:3000
테스트 계정은 `sql/seed.sql` 참고 (전 계정 비밀번호 `admin1234`).

## 자주 겪는 문제

### `/api` 요청이 전부 502

Nginx는 기동 시점에 `proxy_pass http://backend:8080`의 호스트명을 해석해 **IP를 캐싱**한다.
백엔드 컨테이너를 재생성하면 IP가 바뀌는데 Nginx는 옛 IP를 계속 바라본다.

```bash
docker compose restart frontend
```

백엔드를 재생성·재배포한 뒤에는 항상 이 명령이 필요하다.
근본 해결책은 [`배포-체크리스트.md`](배포-체크리스트.md)의 "백엔드 재배포 시 Nginx 502" 항목 참고.

### DB 인증 실패 (`password authentication failed for user "retrack"`)

`POSTGRES_PASSWORD`는 **볼륨을 처음 만들 때만** 적용된다.
이미 `retrack_postgres-data` 볼륨이 있는 상태에서 `.env`의 `DB_PASSWORD`만 바꾸면
DB 계정의 실제 비밀번호는 그대로여서 백엔드가 접속하지 못한다.

```bash
# 방법 1 — 데이터를 유지하며 계정 비밀번호만 변경 (권장)
docker exec retrack-db psql -U retrack -d retrack \
  -c "ALTER USER retrack WITH PASSWORD '<.env에 넣은 값>';"
docker compose up -d

# 방법 2 — 볼륨을 지우고 처음부터 (로컬 데이터 전부 삭제, schema.sql + seed.sql 재적용)
docker compose down -v
docker compose up -d
```

Mac에서 **처음 띄우는 경우라면** 볼륨이 없으므로 `.env` 값이 그대로 적용되어 이 단계가 불필요하다.

### 코드를 고쳤는데 반영이 안 됨

`spring-db.xml`을 포함한 백엔드 소스는 WAR에 패키징된다.
컨테이너 재시작만으로는 반영되지 않으니 **재빌드 후 재기동**한다.

```bash
mvn -f backend/pom.xml clean package
docker compose up -d
docker compose restart frontend
```

### 기존 로그인이 401로 튕김

`JWT_SECRET`을 바꾸면 이전에 발급된 토큰은 전부 무효가 된다. 재로그인하면 된다.
