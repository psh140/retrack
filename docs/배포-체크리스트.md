## 1. 코드 준비 (배포 전 필수)

### 1-1. 시크릿 분리 — 최우선

`docker-compose.yml`에 운영 자격증명이 평문으로 들어 있고 이미 git에 커밋되어 있다.

| 위치 | 현재 값 | 조치 |
|---|---|---|
| `docker-compose.yml:8` | `POSTGRES_PASSWORD: retrack1234` | `${DB_PASSWORD}`로 치환 |
| `docker-compose.yml:31` | `DB_PASSWORD: retrack1234` | `${DB_PASSWORD}`로 치환 |
| `docker-compose.yml:32` | `JWT_SECRET: retrack-secret-...` | `${JWT_SECRET}`로 치환 |

- 메일 계정(`MAIL_USERNAME`, `MAIL_PASSWORD`)은 이미 `.env` 참조 방식이므로 동일하게 맞춘다.
- `.env.example`에 새 키(`DB_PASSWORD`, `JWT_SECRET`)를 추가한다.
- **저장소가 공개 상태라면 JWT 서명키가 이미 노출된 것이므로 값 자체를 새로 발급한다.**
  기존 키로 발급된 토큰은 모두 무효가 되어 재로그인이 필요하다.
- `.gitignore`에 `*.env`가 있어 `.env` 자체는 추적되지 않는다.

### 1-2. 운영용 compose 오버라이드 작성

`docker-compose.prod.yml`을 새로 만들고, 개발 전용 설정을 운영에서 걷어낸다.
로컬 개발 환경(`docker-compose.yml`)은 그대로 두고 EC2에서만 오버라이드를 적용한다.

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

| 대상 | 현재 | 운영에서 |
|---|---|---|
| `docker-compose.yml:14` seed.sql 마운트 | 테스트 데이터 자동 주입 | 제거 (파일 주석에도 "운영 시 이 줄 제거"로 명시됨) |
| `docker-compose.yml:9-10` DB `5432:5432` | 호스트에 노출 | 노출 제거 — 백엔드가 같은 도커 네트워크로 접근 |
| `docker-compose.yml:19-20` 백엔드 `8080:8080` | 호스트에 노출 | 노출 제거 — Nginx가 `/api`를 프록시 |

### 1-3. HTTPS용 nginx 설정 (도메인 확정 후)

현재 `frontend/nginx.conf`에는 80 포트 블록만 있다.

- [ ] 443 서버 블록 + 인증서 경로 추가
- [ ] HTTP → HTTPS 리다이렉트 추가
- [ ] `server_name _;` → 실제 도메인으로 변경

- [ ] **키페어 발급** 및 SSH 접속 확인
